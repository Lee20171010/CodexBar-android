# CodexBar for Android v0.8.0

This is a stable authentication-reliability release, not a beta. It rebuilds Claude setup around the official Claude Code CLI, prevents temporary Codex network failures from looking like permanent sign-outs, and makes the Dashboard and Connections screen report the same verified account state.

## Claude setup rebuilt around the official CLI

- Replaces direct Claude access/refresh-token entry with a private local companion that drives the official Claude Code `/usage` view.
- Keeps Anthropic authentication, prompts, responses, files, email addresses, and raw terminal content on the computer.
- Sends only validated quota windows, percentages, reset times, a known plan label, and freshness to Android.
- Adds a non-browsable `CBCLAUDE1` pairing format and an in-app Google Code Scanner flow so the pairing password is not handed to a browser or external camera app.
- Authenticates requests with HMAC-SHA256, rejects stale or replayed nonces, rate-limits clients, and encrypts snapshots with AES-256-GCM.
- Reuses one tools-disabled Claude Code terminal and waits for `/usage` loading and rendering to stabilize instead of opening a new session for every refresh.
- Selects the computer's default-route Wi-Fi/Ethernet address while avoiding common virtual adapters, and prints alternative addresses for troubleshooting.

Existing legacy Claude token records are removed during the secure-store migration because that unsupported direct-token path is no longer used. Claude users must pair the new companion once after updating.

## Codex stays connected through temporary failures

- Matches the current official Codex refresh request shape and tracks token expiry instead of refreshing on a fixed six-hour guess.
- Preserves the OpenAI account identifier used for workspace routing.
- Keeps the saved account during DNS failures, rate limiting, provider 5xx responses, and other temporary network errors.
- Requests re-authentication only for confirmed terminal failures such as an invalidated refresh grant or an authenticated 401 response.
- Saves rotated credentials under their new fingerprint so future refresh scheduling follows the current token generation.

## One connection state everywhere

- Dashboard refreshes, background work, and Connections now publish and consume the same persisted provider-health state.
- Distinguishes **Connected**, **Offline**, **Re-authentication required**, and **Saved · verification pending**.
- A stored credential is no longer counted or labelled as connected until a provider request verifies it.

## Install or update

1. Download `app-release.apk` from the assets below.
2. Optionally compare its SHA-256 digest with `SHA256SUMS`.
3. Install it directly over v0.7.0 to preserve encrypted provider connections, preferences, quota history, and widget configuration. Do not uninstall first unless Android reports an unavoidable signer conflict.
4. Claude users should also download `CodexBar-Claude-Companion-v0.8.0.zip`, install the current official Claude Code CLI and Node.js 20 or newer, confirm `/usage` works, then follow the companion README and scan its QR inside CodexBar.
5. Gemini users should use `CodexBar-Gemini-Companion-v0.8.0.zip`.
6. For local Codex context/token insight, use `CodexBar-Codex-Telemetry-Companion-v0.8.0.zip`.

Keep companion computers and Android on the same trusted Wi-Fi. Permit Node.js only on private networks, keep both clocks automatic, and never expose a companion port through router forwarding or a public tunnel.

## Release verification and artifacts

- Android unit tests, strict dependency verification, lint, and debug APK assembly passed before publication.
- Claude companion syntax, eight protocol/parser/session tests, native Windows PTY spawning, and dependency audit passed locally.
- CI repeats Claude native PTY installation and spawning on Linux, Windows, and macOS.
- The tag workflow builds and smoke-tests the production-signed APK, publishes the APK and AAB, packages all three companions, extracts and retests the Claude ZIP, generates CycloneDX SBOMs and checksums, and creates GitHub build attestations.

The APK uses the same pinned production signing certificate as v0.7.0. A signature-conflict warning means the installed app came from another signer; uninstalling deletes local credentials and settings, so verify the APK source first.
