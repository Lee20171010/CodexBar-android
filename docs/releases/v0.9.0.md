# CodexBar for Android v0.9.0

This stable release repairs home screen widgets that never left their loading layout, removes the most common reason to re-pair the Claude companion, and rebuilds what the Android 16 / One UI Now Bar entry and the dashboard actually show.

## Widgets always render

- Every setup read that ran before the widget composed is now guarded and time bounded, so a missing App Widget ID, an unreadable configuration, or a slow credential cache can no longer abort the update and leave the launcher on **Loading…** permanently.
- The widget resolves the application's own credential and configuration managers instead of building new ones on every launcher update. The previous behavior re-ran the legacy preferences migration and warmed a second Android Keystore-backed cache inside a broadcast.
- Decrypting a stored credential no longer reloads the Android Keystore for each value. A cold read performed dozens of binder round trips, which is the work most likely to outlast a broadcast on a loaded device.
- If Glance still cannot compose after its retries, the widget is replaced with a tappable message instead of an inert loading tile. The configuration placeholder is tappable too while the first render is pending.
- The empty state explains how to continue rather than showing only "No services configured".

## Widgets follow the launcher's theme

- Surfaces and labels come from `GlanceTheme`, which picks up Android dynamic color where the launcher offers it, instead of a fixed dark scrim with white text.
- Severity and placeholder colors moved into resources with a `values-night` variant, so remaining quota stays readable on a light launcher.
- The widget picker preview uses the same colors, leaving only provider brand dots as literal values.

## Claude connects with fewer steps and stays connected

- A companion that becomes unreachable is looked for again on the subnet the phone is already attached to, on the paired port only. The stored pairing key must authenticate the encrypted snapshot before the new address is saved, so a host that merely listens on that port cannot take over the connection.
- A terminal authentication failure never starts a scan, and a cooldown keeps a companion that is simply switched off from scanning on every refresh.
- A whole pairing code now pairs immediately, whether it arrives from the in-app QR scanner or from the clipboard, instead of requiring a second **Pair** tap.
- A pairing code can be pasted out of whatever was copied, and a manually entered code can be shown while it is checked.

## The Now Bar entry is worth reading

- The collapsed entry names the provider and its remaining quota instead of a constant app-level label and the used percentage the progress bar already showed.
- Expanding it summarizes the other monitored providers on one line.
- The progress track is split along the warning and critical thresholds, so the filled portion shows which band usage has reached.
- Tapping the entry opens that provider's detail. Notifications carry the provider on the existing internal dashboard link.

## The dashboard leads with the answer

- A summary card opens the list with the quota window running out first, its reset and pace, and a tappable strip of every provider's remaining quota.
- A needs-attention filter appears once a provider is failing.
- The app bar is the collapsing large variant with an explicit refresh action, so refreshing no longer depends on discovering the pull gesture.

## Compatibility

No credential format or local database migration is included. Existing encrypted connections, usage history, widget configuration, and preferences remain compatible with v0.8.1. The companion archives are republished as v0.9.0 and remain protocol-compatible with v0.8.x installations.

## Install or update

1. Download `app-release.apk` from the assets below.
2. Optionally compare its SHA-256 digest with `SHA256SUMS`.
3. Install it directly over v0.8.1. Do not uninstall first, because uninstalling removes local credentials and preferences.
